# Documentation map

| Where | What | Lifecycle |
|---|---|---|
| `../ARCHITECTURE.md` | How the code is arranged today | Updated when the shape changes |
| `../AGENTS.md` | Commands and rules for working here | Short; pointers and hard rules only |
| `specs/<area>.md` | Living specs: what the system does TODAY | Updated in the same commit as the behavior |
| `adr/NNNN-*.md` | One decision each, with what was rejected | Never edited; superseded by a newer ADR that links back |
| `../design-system/` | Tokens, previews, the Freya handoff contract | Regenerated by `design-system/tools` |

## Rules

1. A change in behavior updates its spec in the same commit.
2. Every spec starts with `- last-verified: <date>` and `- owner-paths: <globs>`. `tests/repo_hygiene.rs` fails when a listed
   path matches nothing, so a spec cannot outlive the code it describes unnoticed.
3. A spec states invariants and names the owner paths. It does not list every function or variant; the code already has that.
4. ADRs are never edited. A decision that changes gets a new ADR that says what it supersedes.
5. Write what is true now. Git is the changelog.
